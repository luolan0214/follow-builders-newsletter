Podcast: Parag Agrawal — Building a New Web for AI Agents / 播客：Parag Agrawal——为 AI Agent 造一张新网

Training Data 专访 Parallel 创始人（前 Twitter CEO）Parag Agrawal：人类点击数据是 bug、Shapley 值分配内容方收益、TurboNow 最快 agent 搜索、Google Cloud 合作。完整 transcript（50405 字符）已全文翻译。

TD
Training Data
Parag Agrawal（Parallel 创始人，前 Twitter CEO）
中文

Training Data：专访 Parallel 创始人、前 Twitter CEO Parag Agrawal——为 agent 重造搜索与互联网经济。一期把「agent 搜索」从爬虫讲到收益分配的重磅对话：人类点击数据是 bug；先做搜索 agent 再做搜索引擎；放弃延迟两年后 TurboNow 一鸣惊人；与 Google Cloud 达成企业 agent API 搜索与 grounding 提供方合作；用 Shapley 值给内容方分钱；公司原名竟叫 Shapley Inc.。

【Parallel 是什么：为 agent 的千倍搜索】

Agrawal：在 Parallel，我们构建让 agent 搜索并使用网络的技术。就像人类学会了用浏览器和搜索引擎点进点出去获取信息，agent 也需要做同样的事。我们创业的赌注是：agent 的搜索量将是人类的一千倍——因此需要重造支撑 agent 搜索的技术，以及与之配套的商业模式。

Agrawal：我在 Twitter 做高管时，那是一个远超 PMF、数亿用户每天用三十多分钟的产品，反馈回路来自海量用户。而 Parallel 是一家 pre-PMF 公司，前提是几年后互联网上会出现一类新客户——我们在为那个还不存在的客户、每天都在学习的东西做技术。两种世界运转方式完全不同，我在「反学习」Twitter 的经验。

【搜索的本质与破局】

Agrawal：网络搜索的问题：你要找东西但不知道它在哪。搜索引擎爬取全网、读入并组织成索引，查询到来时经多级检索与排序，把几千亿网页收窄到最相关的少数——本质是「千亿对千亿」的匹配问题。每次查询约等于：从万亿网页里给我一千个 token，而且要是对的那一千个。

Agrawal：过去难在两点：爬全网建索引贵；更关键的是缺「这个结果比那个好」的反馈数据——人类评分和点击数据都难以规模化获得。现在模型把专家级评分数据变得极便宜。我们的核心观点：人类点击数据是 bug——agent 用搜索干活应该依赖 agent 反馈，而非人类反馈。

Agrawal：破局是不先做搜索引擎、先做搜索 agent：查询到来后现场爬。深度研究场景里用户能等一分钟甚至十分钟——只要有足够好的地图知道优先爬哪里，用「推理时算力」换「索引」这个延迟优化。早期客户：保险承保与理赔、销售数据增强、金融建模数据管道——都是替代「外包人类策展网络数据」的场景，也让我们用真实用例而非理论 eval 积累经验。

【质量、成本、延迟】

Agrawal：公司建立在质量、成本、延迟三个维度上。前两年我们刻意忽略延迟，先在每个价位做到最佳质量——蒸馏到小模型是已知技艺而非未知研究。达标后我们发布 TurboNow：市场上最快、质量最高的 agent 网络搜索，而且领先很多。

Agrawal：为 agent 服务时界面也变了。人类靠关键词搜索——我们懒，给 Google 打两个不完整的词带个错别字就指望最好结果。模型不那么懒：错别字更少、查询描述更好、查询更长，搜索引擎不用去猜 agent 想要什么。

Agrawal：那些「pre-AI 人类 slop」（SEO 联盟页）之所以存在，是因为它在迎合懒惰的人类：权威数字在第 73 页的 PDF 里，但没人愿意翻。对 agent，我们直接从最权威处取摘录送进上下文——不必被迫做这种权衡。查询进来后：模型理解并改写查询、路由到不同索引（大索引/新鲜索引/结构化索引）、多级检索排序、逐级用更大的模型，最终带回信号最高的一千个 token。

【与模型公司的关系】

Agrawal：有人认为搜索如此根本、模型公司会自己做。我没看到地面证据：预训练爬虫对建新鲜索引没什么用——模型公司没有耐心做完人主义者，等慢吞吞的 JavaScript 加载，token/算力比太差；而我们恰恰要爬这些。但搜索确实是每个 agent 的核心邻接：买 LLM 干活的用例里十个有九个要联网。所以自建还是购买——对话会继续。今天我们宣布与 Google Cloud 合作：成为其企业 agent API 的搜索与 grounding 提供方，与 Google 搜索并列。

【千倍搜索与背景 agent】

Agrawal：一次人类动作现在是搜索量的乘数。ChatGPT 里每条提示做 5-10 次搜索；调高档做几百上千次。更大的乘数在背景 agent：给一万家小贷商户做月度风险巡检的 agent，一次运行就是几十万上百万次搜索——过去每月一次的人工流程现在每周跑。我用 Notion 的自定义 agent 给每次会议做预习文档——一次写好提示，它为我的每个会议做几十上百次网络搜索。背景 agent 的部署只受「价值/花费」比约束。

Agrawal：现在 agent 查询超过人类了吗？还没有，我们还非常早期——走出我们的泡泡，没人听说过 Fable。像我这样的人可能已经运行在千倍档；Cloudflare 监测显示 AI 流量的页面读取量已与人类流量相当。方向是明确的。

【互联网经济与 Shapley 值】

Agrawal：广告是极高效的差异化定价机制——Google 在大多数查询上亏钱、靠少数赚回，才有免费搜索与免费内容。但如果人类不再出现、来的都是 agent，「有限人类注意力换结果」的根基就塌了。我卖过 Twitter 数据给 OpenAI，也在思考什么才激励相容。

Agrawal：我们需要的是：对高质量内容差异化付高价、对高价值工作差异化计费，且能规模化而非逐个谈定制交易。最大属性是激励相容。为什么模型公司要付钱？推理时要新鲜数据、训练要数据、还要既有训练的责任豁免——付的是这三样的组合。

Agrawal：归因怎么做？把某条内容从语料里拿掉，跑 agent，看质量掉了多少；再看花一分钱算力能否把质量补回来——如果能，这份源大概值一分钱。这个直觉的形式化就是 Shapley 值：合作创造了大于各部分之和的饼，如何分才能让人人都有激励继续合作。直接算 Shapley 比付给出版方的钱还贵，但可以用模拟数据训练模型来很好地估计它。就像广告界从手动出价走到自动 ROI 出价——反馈回路一旦建立，市场就会收敛。

Agrawal：宏观账也算得过来：把 LLM 知识工作推理开销的 2-10% 分给网络数据，就超过今天 Facebook/LinkedIn 之外全部网络数据商业模式的总和。按 agent 网上规模每年一个数量级的增速，12-24 个月内这套数学就能给范围很广的内容方带来有意义的收入。想象一下跟内容方解释 Shapley 数学的场景——需要一点时间，但性质他们爱听：独特数据多得、银行家读一次比退休老爸读一次付得多。

【为什么叫 Parallel】

Agrawal：公司原名是 Shapley Inc.——注册时 shapley.ai 恰好可用（shapley.com 是个停放的色情域名）。后来我们越来越喜欢 Parallel：一方面当时在并行做很多事情；另一方面我们预见到一张「为 AI 而建的平行网络」——你发布时会想两个受众：人类怎么读，agent 怎么读。双重发布、平行网络。

（另一位主持人补充：财报电话会就是已翻转的例子——通过 agent 消费财报转写的人几乎肯定比听音频、甚至读转写的人多。若我是上市公司 CEO，我会明确说：我讲的每句话都会被 agent 正确转写与解读。）
