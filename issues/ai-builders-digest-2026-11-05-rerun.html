Podcast: Nebius CTO on Racing the Hyperscalers / 播客：在 AWS 醒来之前

Redpoint Unsupervised Learning Ep 96：Nebius CTO——「我们是 AI Cloud 不是 Neo Cloud；收入是 AWS 的 1%、三年需求看涨百倍」；NVIDIA 新芯片流水线；700 GB/s 单卷吞吐；「整个行业啥都没优化：95% 客户跑的不是原版开源模型」；唯一瓶颈是执行力；AI 负载正在重新变成代码。62067 字符全文翻译。

UL
Unsupervised Learning（Redpoint）Ep 96
Nebius CTO
中文

Redpoint 的 Jacob Efron 对话 Nebius CTO——从 Yandex 拆出的 AI 云、如今正面追赶 AWS 和 Google Cloud。要点：软件即护城河（同一平台既服务数万卡互联集群、也服务跑半小时单卡的自助用户）；痛恨 Neo Cloud 一词（玩家从五七家膨胀到三五百家）——「我们是 AI Cloud，下一个对手是 AWS」；收入约为 AWS 的 1%、但三年需求看涨十倍到百倍；Yandex 拆分起源与全部推倒重写；软件优先（2024 年硬件 40-50 人 vs 软件 200 人）；NVIDIA 新芯片流水线（提前一年看原理图、样片与上月不同、首批建集群撞没人见过的 bug、提补丁上游）；客户分化在成熟度而非规模（neo lab 十亿美元合同不在乎 GPU 在法国还是冰岛；企业要认证与源码审查）；存储意外（单一共享卷打出 700 GB/s）；延迟与成本是 100% 软件问题；disagg 推理人人谈没人做对；「整个行业啥都没优化」——95% 客户跑的不是原版开源模型、限定领域也许不需要前沿尺寸；收购（模型优化人才并购、Tavily 与自研沙箱）；数据中心墙内全按自家标准；唯一瓶颈是执行力（变压器交期数年、项目经理最稀缺）；超大规模云为何没赢（芯片短缺+内部腾挪+改造惯性，走出短缺后全销售火力进场——赌自己长得够快）；终局（三五百家不会全活、但利基不等于小）；OpenAI×Baseten（账单震惊的回应、单一触点策略）；管理组织保守前进（agent 产出是你的责任、完全自主 agent 不碰核心服务——「见过香肠怎么做的」）；最大失误是低估单一客户规模（30 兆瓦不够一个客户用）；现在盯「结果优化」（按结果竞价、harness 随任务演化、AI 负载重新变成代码——agent 跑几分钟不调一次 LLM）。完整译文见下。

【冷开场：如果 NVIDIA 产能是十倍】

「如果 NVIDIA 能多造十倍的芯片，这整个市场的形态都会不一样。对超大规模云来说，这不只是销售问题——还牵涉把为其他负载大规模建好的基础设施改掉。这是一笔必须由潜在业务规模来证明合理性的巨额投资，而眼下还到不了那个量级。」

【市场格局：我们是 AI Cloud，不是 Neo Cloud】

主持人 Jacob Efron（Redpoint）：聊聊 AI 云市场的格局？有人说「重要的是拿到 GPU，哪有去哪」。

Nebius CTO：我显然有立场——我是软件出身，我们的产品从第一天起就建立在「软件即护城河」上：用同一个平台，既能服务消耗数万张 GPU、单一互联互通集群的大客户，也能服务跑半小时单卡的自助用户。大规模建设、却几乎像零售一样出售——这是我们从一开始的价值主张，也是我们与市场所有人的区别。

顺便说：我痛恨 Neo Cloud 这个词。它最初是区分「做这件奇怪新事的云公司」，后来人人都想挤进这个市场——起步时这个领域五到七家，现在三到五百家（取决于你愿意把什么算进来）。我们不再要这个被撑大的伞形术语：我们是 AI Cloud，我们过了那个阶段，下一个竞争对象是 AWS 和 Google Cloud。是的，我们小得多——收入大概是 AWS 的 1%——但我们跑得快，服务一个非常特定的市场，并且押注这个市场即将爆炸：未来三年总需求会涨十倍、甚至百倍。我们才刚挠到表面。现在那些巨大的算力设施很多是自有自用的（马斯克的 Colossus 是真大规模，但不面向公开市场）；Anthropic 和 OpenAI 在搅动产能，但那是为自家产品。Google、Meta、微软则在「租给市场 vs 留给内部团队」之间不停腾挪。我们的赌注：存在一个独立于大厂（没有巨额内部消耗）的玩家生态位，服务那些「想成为大公司的中型玩家」。

【起源：与 Yandex 分家，全部推倒重写】

公司 2024 年完成与 Yandex 的拆分——与俄罗斯资产再无关联、白纸一张。

Yandex 的遗产有多重要？硬件侧：核心团队从 Yandex 带来「真规模」的运维经验——几十万、上百万台服务器、多个机房，他们是初期建设与扩张的骨干，没有他们我们不会这么成功。软件侧则一言难尽：一切必须从零重写（旧经验基本作废）；而且扩张太快，到 2024 年底新平台上线时，软件工程团队里相当一部分已经不是 Yandex 的人了。

方向上我们笃定：不做托管裸金属、不做第三方服务拼盘，要做整体统一的云平台。自建服务器与机箱、写固件、建网络——2024 年硬件团队四五十人时，软件组织已经两百人。我们自认是软件优先的公司：在坚实的硬件地基上造云。那些从加密货币等背景进来的人，思路多是「买 GPU、跑起来、找到买家」。

【新芯片上线流水线：一年预演、样片、补丁】

和 NVIDIA 的流程「乱——是好意义上的乱」。远在发布前一年，NVIDIA 会给你看原型和原理图：内部怎么优化、PCI 连接在哪、下一代平台长什么样。过一阵来说「我们优化过了、会不一样」；再来「有实验室样片了，要看吗」——「当然」——「哦对了，它跟两个月前给你们看的不一样」。所有人在时间上都被压缩，NVIDIA 也在流片过程中持续迭代。不像消费市场：今天的 iPhone 三年前就规划好、一年前定稿、最后一年打磨。AI 市场的节奏是：发布都只是指示性的。

到样片接近量产版，你开始建设：把新硬件的支持、新限制/新能力整合进软件平台；解决负载隔离（我们是云、不是裸金属——虚拟化、存储、网络都得工作）。有时我们冲在最前面——某些代际可能是最早建成某规模集群的团队之一，撞上没人见过的软件问题，报回 NVIDIA、提补丁、等修复。比如从 B300 到 GB300：隔离架构不同、以「机架」而非「服务器」为单位——得想出机架级维护的办法、把负载迁走。总之每天推一点，最后就有产品、有客户在用。

【客户差异：成熟度，而非规模】

负载本身差异不大——训练或推理，长得都差不多。我们当年低估的是存储：GPU 固然最重要，但伴随训练的是海量存储需求——拼的是吞吐与延迟。以前谈网络存储用 GB/s，现在客户 routinely 从单个共享卷打出五六七百 GB/s 的吞吐、接上千台 GPU 服务器——两年前我根本不敢想，现在成了预期。而基线拉到这么高，你就能服务任何人。

真正的客户分化在成熟度：新建的 neo lab 动辄数十亿融资、大部分预算进算力——十亿美元的合同，人家只在乎 GPU、存储、性能、可用性，连位置都不在乎（美国？法国？冰岛？无所谓）。而企业客户合同小得多、但有下游客户、有合规要求——认证、安全审计、「让我们看你们源码」「你们怎么防攻击向量 Y」。这才是做「真正的云」的部分，也是与规模和性能相比真正差异化的东西。

【延迟与成本：100% 在软件层解决】

延迟敏感客户小 batch、后台 agent 客户无所谓——这不是靠硬件或集群构造解决的。前提自始至终：通用云平台、基线高到装下绝大多数负载。之后的 SLA 游戏（首 token 延迟、请求总延迟）全部发生在软件层：编排层、模型层、一路往上到请求从端点到推理器的路径与沿途损耗。100% 软件。

【Disagg 推理：人人都在谈、没人做对】

预填充分离（prefill/decode 分离）这个阶段人人谈、没人做对——这是个复杂问题，而且推理里有大量低垂得多的果子可以先摘。我们很谨慎：它不是所有客户所有负载的默认解；围绕它做 SLA 到今天都很难。原型服务里有不错的成果；最有需求的客户的生产环境里也有分离式部署——但偏手工。有意思的是：对于新一代 GB 级 NVLink 机架（机架内互连快到飞起），以前分离式的很多难题在「能塞进一个机架」的前提下就自动解决了——剩下的是按客户流量模式配平 prefill/decode 节点、以及一 rack 两负载的装箱问题。云侧这个产品只按整机架卖；托管推理侧则可以混布。

【低垂的果子：「整个行业啥都没优化」】

恕我直言：整个行业根本没怎么优化。跑推理——尤其是跑如今这批开放权重模型——远不是已解决的问题：拿开源推理服务器对新模型的初始支持直接跑，结果多半乏善可陈——不够快、不够便宜（按现在的基建价格），还不如直接用 Fable 5.1、Astra 6。但正因为架构开放，你可以优化请求处理、推理服务器配置、针对特定流量模式做内核优化（有时是过度优化）；模型权重侧的潜力也远未挖完：不止投机解码，还有剪枝、选择性剪枝、压缩。

我们客户里 95% 不跑原版开源模型——全是改过的、微调过的。这意味它们面向特定用例；特定用例通常是限定领域；限定领域意味着：你只需要在特定子任务上保留前沿智能与推理能力，其余不在乎——也许你根本不需要这么大的模型，只需要一个「对该任务选择性压缩」的模型。这当然不适用于开放式 deep research 或宽域编码。但我坚信：真正的企业级 AI 落地会越来越走向专业 agent、限定领域——那时你甚至不再在乎成本，而在乎结果的可预测性与拿到结果的分秒级时间。这里还会出几个漂亮突破。

【收购与平台化：Tavily、沙箱与 agentic 工具】

我们想在一切前沿。这些优化是加法甚至乘法。今夏初的一笔收购就是冲着人才去的——模型优化、压缩、投机解码——与既有团队合并后规模翻倍：数十人专攻，内核优化、模型压缩各有专项小组。想认真做推理即服务，今天这是唯一路径。

Tavily 那笔：一年前就被产品和 go-to-market 惊艳；我们知道自己底层技术与大规模网页索引的专长能让他们跑得更快（跑一个网页搜索引擎一点也不简单）。它与现有产品线的整合在探索中——我们在为托管推理配 agentic 工具：我们如今也自研沙箱，这是人们搭 agent 的积木之一，还有几个更早期产品在路上。

【数据中心：墙里的一切都归我们控】

老实说我不知道机房的墙是什么造的。但墙内的一切完全由我们掌控：我们不租「自带网络、自带 GPU」的机房；租的话只租楼和电，内部建设全部按我们的标准来。最近还宣布了「轻资产模式」：第三方出资本建设施和 GPU，我们把平台架上去跑——体验完全一致。我们从不把租来的东西包装成自己的云：在 Nebius 开一台虚机，可以确定它从上到下跑在我们的栈上。

【瓶颈只有一个人：你的执行力】

问哪个是关键瓶颈——电力？人力？散热？网络？HBM？我只能说一个：你的执行力。GPU 短缺、组件短缺、如今 CPU 短缺、NVMe 短缺、机房不够、电不够、合格工人不够、网络收发器不够、变压器——你知道变压器现在交期多久吗？好几年。所以一切都是问题，而唯一能筑起的护城河是：围绕这一切的执行能力——采购能力、在该抄近路的地方抄近路、在设施之间灵活腾挪（把这个挪过去、把这个推迟、那个就能赶上）。这个领域里，有经验的项目经理大概是我职业生涯里见过最稀缺的：脑子里装着全局问题、还能在其中导航——这本身就是护城河。

【负载变了又怎样：负载就是负载】

长程 agent、后训练、开源模型——负载就是负载。基线够高就不受约束，剩下是优化问题：怎么装箱、怎么切分、怎么混布、暴露哪些原语。新一代 NVIDIA 互连架构（转写含混，与 Groq 交易相关）也只是「再加半代」：连接方式新、有些限制，效率有增益，是平台的一个小众补充。定制的部分远比你想象的少。

【超大规模云为什么没赢：产能、内部消耗与改造惯性】

首先纠正「他们没试」的印象——他们从这个市场拿到可观的大单，真实成交价远比挂牌价有竞争力。两个原因：一、内部消耗与对外出租的腾挪，且我们身处芯片短缺的世界——如果 NVIDIA 产能是十倍，微软和 Google 会既自用又供给市场，整个市场形态都会不同；因为产能对他们的规模而言不够，这块业务在他们的盘子里相对就小：对 AWS 这种体量，几十亿美元不是小钱但也不够改造「为其他负载建成的网络/吞吐/存储」这套基础设施——那是必须由业务规模证明合理性的巨额投资，而它还不到那一步。等两三年、五年后走出芯片短缺，他们会更重视、会投入、会重组内部去适配这些需求，然后用全部销售火力来抢这个市场。问题是：到那天，我们这些新玩家长得够不够快、能不能以平等身份同场竞技。我们的赌注是：够快。

【三到五百家 Neo Cloud 的终局】

AI 消费会无处不在，就像今天的 web 服务。市场会有 AWS，也会有 Hetzner、DigitalOcean、Linode 和长尾本地托管商。现在这三五百家五年后全活着？不一定——会有整合、有死亡、有新玩家。但这个市场会持续吸引资本，五年后仍会有几百家玩家各有所长。DigitalOcean 并没有因为 AWS 增长而死。

【什么会被吞并、什么会独立】

会复刻上一代云的剧本：增长压力逼你扩品类（否则撑不起估值预测）。OpenAI 有模型、有推理、有搜索（不对外暴露、但平台上的 agent 能用）、有各种沙箱与本地/云端 agent，还在投资 forward deployed 组织去吃传统上德勤、埃森哲的蛋糕——大厂自然会无处不在。但这不意味着一家通吃：今天照样有独立的对象存储玩家、独立算力玩家、小型推理玩家、独立数据库——BigQuery 之外出了 Snowflake，Aurora/Redshift 之外出了 MongoDB 和 ClickHouse。市场太大，利基不等于小——利基可以是solid company。

【OpenAI × Baseten：单一触点的灵活性】

大家对「模型太贵、月底账单吓人」抱怨很多——这可能正是个回应：想试开放模型就去试；反正开放模型仍落后于闭源，给你「降档试用+随时切回前沿」的选项。我喜欢这步棋：说明 OpenAI 不僵化、在探索。而这一切服务于同一个目标：成为单一触点。只要用户还在你的生态里，你总有办法引导他、追加销售、介绍新服务。能消除一个顾虑，何乐不为。

【一年内改变看法的事：AI 编码】

明显的答案是软件工程：一年前是「彻底的胡扯」，现在是日常工具的扎实部分。更个人的：我开始更多依赖本地 agent 与 harness 分担认知负荷。

【管理工程组织：保守地前进】

cautiously、conservatively。slop 在聊天里、merge request 里到处渗出，我试着把控节奏、保持警觉。我们不限制工具使用——预算相当大、不设人均/部门限额——但同时观察使用方式、找出最无效的用法；并且立了一套政策：你用 agent 做的，仍然是你的结果、你的责任、你的 PR、你的代码、你 on call、半夜被叫起来的是你。完全自主 agent 的产出必须打标；完全自主的 agent 暂时不能碰核心服务。有人惊讶于身处 AI 革命公司的我如此保守——但我见过香肠是怎么做的，我会谨慎。

【最大的失误：低估了单一客户的规模】

说出来好笑：我们低估了规模。不是公司增长——我们从一开始就很乐观——而是当今单一客户运转的规模。五年前 30 兆瓦是严肃设施、装几十万台服务器；现在 30 兆瓦有时不够一个客户用，我至今没完全适应。存储同理：四年前网络存储谈的是几百 MB/s，现在客户 routinely 从单一共享文件系统拉七百 GB/s。我是基础设施出身的人，见过各种数字——突然在后面加两个零就叫新常态。仍然费解。

【盯什么：结果优化与「负载重新变成代码」】

我已经不关心新模型更大更聪明——接受它是给定。也在留意新架构，但今天看不到任何值得下小注的东西（希望某个 stealth 实验室里正在憋）。

我越来越感兴趣的是 agent 侧的「结果优化」：我们从谈模型、模型大小、模型家族，转向多轮长程 agent——谈的不再是请求而是结果，公司在按结果竞价。内部有个小组在研究：怎么提高达成结果的概率——不是靠换更大的模型（那当然是一部分），而是引入更复杂（或更简单）的工具、让 harness 随任务演化。这把我们带回可观的 CPU 消耗：现代 AI 工作负载正在重新变回代码——形式化、质量门、复杂工具；有时你的 agent 跑好几分钟都不向后端 LLM 发一个请求。未来 AI 落地很大程度取决于 agentic 场景的可靠性、能否可靠达成结果——模型之外这整圈优化循环，是重要的一环。
