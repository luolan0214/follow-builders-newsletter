No Upper Limit / 不设上限

Levie 双发（**278 赞**）：「每 3-6 个月回去重试以前不可能的事——agent 已能控制任何有 API 的系统」+「从聊天速率的 20-50% 增益到 agent 群不设上限——我们的脑子还没准备好『算力成为可伸缩变量』」；Garry Tan 三连：「你真的会想要自己的软件工厂」（**344 赞**）；Ryo Lu 上海演讲（**704 赞**）：「当我们什么都能做时，我们还知道自己想要什么吗？」

中文

Levie 双发。回访篇（**278 赞**）——「AI 的一个好教训：每 3-6 个月要回去重试一次『以前不可能的事』，看它现在成不成——今天比历史上任何时候都更如此。过去六个月在 computer/tool use、更少 context rot、更强推理、多模态与领域专长上的进步意味着：任何有 API 的东西（甚至很多没有的），agent 都能控制并当作底层能力来用——安全 agent 接现有数据源与安全工具、IT agent 跨软件栈可靠执行工作流、数据 agent 在系统间迁移数据或流程、架构与设计 agent 驱动 CAD——今天不好用的工具会被 agent 友好或开源的替代品换掉。叠加训练进 agent 的领域知识，你得到的是每个职能的自主协作者。」上限篇（256 赞）——「我们正从一个『AI 产出大致等于你跟它来回聊天的速率』的时代，进入『你给一组 agent 出题、它们去干任意大的工作量』的时期——生产率增益从 20-50% 变成没有实际上限。agent 群与并行扇出已经改造了编码；下一个是网络安全——『更多 agent 审更多东西几乎必然赢』；再往后是众多科学领域、几乎肯定包括生命科学。我们的脑子还没为『算力成为可伸缩来解决任何问题的变量』这个新场景布好线——我们习惯于投入时间与产出相关。这正在永远改变。」

Levie：每 3-6 个月重试以前不可能的事；agent 可控制一切有 API 的系统；从 20-50% 增益到不设上限——时间投入与产出的相关性正在永远改变。

English

Levie's pair. Check back in (278): a good lesson in AI is that you need to check back in on the latest every 3 to 6 months to try something that wasn't possible before and see if it works again — never more true than today. Six months of progress on computer and tool use, less context rot, better reasoning, multimodality, deeper domain expertise means anything with an API (and even many things without) can now be controlled and utilized by an agent as an underlying capability: security agents leverage existing data feeds and cyber tooling, IT agents execute workflows reliably across software stacks, data agents migrate data or processes between systems, architect and design agents leverage CAD tools — and today's tools that don't work will be replaced by agent-friendly or OSS tooling. Combined with domain understanding trained into agents, you get autonomous collaborators for every job function.

No upper limit (256): we're moving from an era where AI output comes roughly at the rate you can chat back and forth, to a period where you set a problem for a set of agents to go off and do an arbitrarily large amount of work — productivity gains go from 20-50% to gains that don't really have an upper limit. Agent swarms and fan-out across parallel agents already transformed coding; next, cyber is almost entirely a problem space where more agents reviewing more things wins; then many scientific fields and almost certainly life sciences. Our brains aren't wired for the scenario we're heading into where compute becomes the variable we flex to solve any problem — we're used to time-in correlating with output. That's changing forever.

【课程史：从散落博客到正式课程】

这门课第二次开设。2024 年 11 月萌生想法：编码 agent 还在早期版本，但「开发者干活的方式正在剧变」已经显而易见，而当时所有方法论都散落在博客帖子里。Mihail 是斯坦福校友、一直梦想回校教书回馈，于是找到教《设计机器学习系统》的好友 Chip Hieatt 取经，花了九到十个月走完委员会审批、2025 年秋首讲（那还是 Opus 4.5/4.6 之前的时代），反响热烈、被 Business Insider 报道。今年自主编码 agent 以前所未见的方式起飞，于是全面刷新。

去年和今年的区别？去年更像是「全景 odyssey」：ISDLC（软件开发生命周期）的每个环节都在冒出专门的编码 agent 公司——code review 的、spec 设计的、SRE 的——课程偏向曝光与游览。今年有些原则开始固化：精细的 context engineering、把设计与架构当作处理复杂任务的手段。课程定位是「实践者课程」：不是给初学者的、不替代传统 CS（算法等反而是先修课），而是教你把好基础用到生产环境的巨型代码库上。

【学生焦虑与「地板高得多」】

学生焦虑吗？非常。第一堂课他就说：「我相信每家公司都需要你们——但地板比以前高得多。你以应届生身份入职，但只当『L3』已经不够了：你几乎要一进来就达到准 senior 水平。」所以课程要回答的是：怎么更快到达那里？核心软件工程的基础（系统怎么建、权衡是什么）仍然重要；在此之上，才是人类该有价值的地方——其余实现细节大多可以交给 agent。

Swyx 的暴论（他自己也承认是故意说狠话但真信）：「大多数学生是 cooked（完了），其中一些人会超级值钱。」斯坦福的孩子会没事——但「美国其他人怎么办」是个开放问题。Mihail 周二做的课堂调查：没有一个学生还手写代码——全是本科生二三年级。

【客座讲师与开源贡献作业】

课程大量使用客座讲师，这是 by design：「我是实践者，但宣称自己有全部答案就是 hubris。把真正在前沿、看得比我更远的人请上讲台。」（swyx：相比之下有些课是「名字大全」——而他真的会教你『Claude Code 就是 200 行代码』这种根本性的东西。）

今年最自豪的改动：开源贡献作业。去年九个教学作业（「拿个仓库、用 AI code review 工具发个 review、想想为什么好/不好」）太教学化、基本能被 one-shot——没用。今年改为：与一批最优秀的 AI 原生开源仓库合作（它们本身是编码 agent、或在为 agent 造工具），学生作业就是真的给这些项目贡献代码——维护者会 review 你的 PR、帮你建立好软件的心智模型。这是「好软件设计的接力棒传递」：避免「senior 们带着 pre-agent 时代的功底+agent 变得超强、而 junior 们不知所措」的断层。顺带：Factory、Cognition、OpenAI 都给学生提供了 credits；干得好的学生会被项目方直接挖走。

【课程地图：十周总览】

W1 编码 agent 内部原理——从零造一个编码 agent（「自己写个 Claude 克隆」，幸好它现在开源了）；W2 大规模 context engineering（超越 vanilla prompting）+ 工具设计与 MCP（「MCP 被骂了一阵，但我仍然 pro-MCP：它已是既存标准、会继续存在」）；W3 Skills——从单一用途工具扩展到「程序」，通往 agent 自动化；W4 定制 agent——AgentsMD、Claude MD、hooks、sub-agents 等现代 harness 机制；W5 agent-ready 代码库（最爱的主题之一）：什么是「准备好被 agent 摄入」的仓库——表层边界、文档、可验证性；W6 agentic code review；W7 security；W8 background agents；W9 AI-native 团队；W10/11 software factory——全部层层铺垫、通向工厂。

【W2 上下文工程：子代理扇出与「笨区」】

上下文工程的要点（这也是 AIE 大会一批研究论文的主题）：主 agent 的上下文是稀缺资源，重活应该扇出给子代理（retrieval 型 fan-out 现在已经做得很好）；Claude Code 的系统提示词一度 2 万 token、后来砍掉八成——「模型变强、prompt 变简」的跷跷板反复出现。还有「笨区」（dumb zone）概念：别把模型不需要聪明的地方喂给它。

【W3 Skills 之辩：想要 skills 死掉的人】

Skills 环节请了多位实践者。有趣的是行业分裂：聪明人里不少（OpenAI/Anthropic 内部）希望 skills 死掉——「感觉不 AI-native：说好的 AGI，结果每人抱着一堆 Markdown 文件？」但另一面，skills 确实在无数团队里创造真实价值：Grill Me（让 agent 拷问你的方案）、Explain Diff、网页技能等；写 skill 有手艺——swyx 甚至做了「帮你剪 skill 的 skill」，Eugene Yan 谈过 skill 的修剪园艺学（skills gardening/pruning）；Devin 把组织知识 codify 成 skills 的路线说不定反而活得最久。

【W6 杀死 code review】

编码 agent 时代的新瓶颈是 code review。这周请了 Aviator 的 Ankit（「杀死 code review」）、merge queue 实践、「把 spec 当 PR 描述写」等。讨论延伸到 Git 本身的形态：Basis 的「Git artifacts」——specs 与 canonical state 的分离；swyx 提出更激进的想法：用「程序数据库」替代 Git（Git 是面向 diff 的文本工具，agent 时代我们需要的可能是可查询的程序表示）；任务表示的赢家很可能是 Linear；以及那句结论：每家公司都会变成 coding agent 公司。

【W7 安全：零依赖、日光与 IAM】

安全周请了 Semgrep 的 Isaac。要点：依赖管理/供应链是主战场；「最安全的代码库=零依赖」的极端立场之辩（反方：日光是最好的消毒剂——开源依赖被全世界盯着）；有人主张把关键路径全部 Rust 化（Vercel 的 Malta 一派）；「实验室会给前沿踩刹车」与「模型终将修好所有安全」都未被证明。给学生的具体忠告：代码库里数据、计费、认证、授权这几块「别写代码、去学 IAM 和 DNS」；安全 VC 五年里真正跑出来的只有 Wiz 和 Socket 两家。

【W8 后台 agent：一切都是编码 agent】

Cloudflare 的 Rajesh 讲后台 agent：Stripe 的 Minions、Spotify、Ramp 的 Inspects 等案例；Grokbot 底下其实是 Cursor。swyx 分享自己的用法：把 SEO/AEO 当成一个代码库、在 Codex 里跑循环。趋势判断：everything is a coding agent——一切后台自动化最终都会长成编码 agent 的形态。

【W9 AI 原生团队：网关、MCP portal 与 God box】

这周讲团队与公司层的基建：LLM 网关（现在几乎每家都在自建或买）；MCP portal（「MCP 就是存在了」——swyx 曾向 Anthropic 提议做 portal、后来失去兴趣：portal 本身是门未验证的生意）；以及「God box」收敛论：所有基建最终汇流——MCP portal 折进 LLM 网关、网关再折进 authz 与计费。「N 到 M 再加 N」的架构；Conway 定律——你发布的就是你的组织架构图（你 buy 你的 org chart）；「为所有人做的东西就是为没有人做的」——AIE 的受众是真正在乎 AI 的工程师；未来角色是 platform engineer：一个人 owning 云、DevEx、SecOps（「大男孩做平台，产品同学调 CSS」）。

【W11 软件工厂：造机器的机器】

压轴主题：software factory——「造那台机器的机器」。人类只剩两个卡点：intent（意图）与 review（审查）。OpenAI 那篇 harness engineering 博文是标志：内部工具五个月零行手写代码。但 GTM 是 land-and-expand：没法把一座整厂直接空降给福特；Warp 给学生开了「在工厂里干活」的版本。开发者角色变成「agent 的管理者」、PM-工程师混合体（Anthropic 平台的产品负责人与工程负责人至今还没合并成一个岗位）。「写会写 prompt 的 prompt」——要向上搭到工厂、不要从工厂向下漏：slop 都是从向下搭里漏出来的。度量：今天还在用 PR 合并率，两年后会显得可笑；转向 CSAT 类指标。期末项目从 YC RFS 出题：有 EE 学生给 C 语言手册做了翻译器；有设计师把笔记本拍照变成 Vercel 应用、现在真的在 Vercel 做 Eve。Meta-harnesses：像模型路由器包 API 一样把 harness 包起来。

请了 Steve Yegge 讲「精神病等级」：十级、农场、Gastown 烧掉——「在 Gastown 建成的唯一有用的东西就是 Gastown。」swyx：我不会雇任何没经历过这种 psychosis 并走出来的人；学生版 psychosis 的仿品是「在 Notion 里画图但不 ship」。Boris Cherny 的班级分享给了五阶段框架（从零数）：gated→assisted→parallel→supervised autonomy→AI native——Anthropic 整体在第三阶段、Boris 本人第四。还有 Anthropic 内部术语 dynamic workflows：按需现场写一个 harness 作为子代理（比复制父 agent 写更多代码）；Monaco 给 GTM 场景造了一版。

【Monaco 插曲：一家 GTM 公司的 AI 原生实践】

（中段插播 Mihail 的本职。）Monaco：赢了 monaco.com 域名官司；两架飞机每天 6000 美元的营销事件正满天飞；Series B、总部 SF、all-in-one 的 AI 原生销售平台（客户从 seed 到 Series A、正在上探）。AI 侧：自建 GTM 的 agentic harness（灵感取自 Codex/Claude 这类编码 harness）——TAM/ICP 评分、pipeline 演进、会议纪要等销售琐事全由长/短程 agent 驱动。模型策略走了典型曲线：先用前沿模型探明可能性→（Harvey 毛利之争那类成本压力）→进入「post-train 开放权重」阶段，用 RL 环境后训专用模型。enrichment 供应商：Parallel 与 Exa（都是朋友，保持中立）；自建「世界数据库」——公司与联系人全景，ICP 构建时永远最新。Monaco 自认「demand 方向世界级」：找对买家、找对时机（比如检测到销售 VP 换工作的信号——换工作的人正处在最可能采购新平台的窗口）。最独特的资产是 forward-deploy AE：卖 Monaco 的世界级 GTM 团队同时就是帮客户 onboard agentic 工作流的顾问——把 Brex 系的 GTM 最佳实践 codify 进平台。

工程侧：Monocoder——架在 Coder 平台上的自家版后台 agent 基建（致敬 John Tracy）；Hal——Slack 里的 AI SRE+客户成功+QA 工程师三合一 bot（对不同受众展现不同人格；致敬 Yunja）。build vs buy 原则：「buy to learn, build to keep（买来学、留下的是自建的）」。code review 工具的采纳故事：一年多前系统调研过 CodeRabbit/Graphite/Ellipsis 等，都没过线；后来 Devin（Cognition）在课堂上被有机安利、团队一个个主动要求加入——第一次是统计驱动的选型（PR 饼图：解决什么、噪音换价值划算吗），第二次纯靠有机口碑。AI SRE 领域看好 Resolve 与 Night Shift（Greylock 投）。

【结尾：野心、招募与 benchmarks】

给学生的最后忠告：课程学分之外，最值钱的敲门砖是 benchmarks 和 evals——「能进每一家前沿实验室的门」；Sweet Bench 就是个本科生的项目；benchmarks 里有真金白银。还有招募故事：Cursor 的 Wilson 当年放话「我要写个浏览器」——这种野心本身就该被招募；今天「拍张照变成 app」已经不算野心了——标准在飞速抬高。
