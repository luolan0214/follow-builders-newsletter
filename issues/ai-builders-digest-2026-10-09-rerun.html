Podcast: Why Every Traded Personal Agents for One Company Agent / 播客：Every 为什么放弃个人 agent 转向公司 agent

AI & I by Every 全新一期（2026-10-07 发布，本刊首次收录）：Dan Shipper × 平台负责人 Willie Williams 复盘从 OpenClaw 群魔乱舞到 Plus One 之死再到 Every Agent 诞生，以及 Dots 时代的个人/公司双轨预判。完整 transcript（36725 字符）已全文翻译。

A&
AI & I by Every
Dan Shipper（Every CEO）× Willie Williams（Every 平台负责人）
中文

AI & I by Every 全新一期（10-07 发布，本刊首次收录）：Dan Shipper 与平台负责人 Willie Williams 复盘「为什么 Every 从人手一个个人 agent 转向一个公司 agent」——从 OpenClaw 群魔乱舞到 Plus One 失败（RIP）再到 Every Agent 诞生，以及 Dots 时代的个人/公司双轨预判。完整译文见下。

【开场：Dots 第二周实测】

Shipper 开场：现在最热的是 Dots——OpenAI 的常驻 agent。DevDay 发布时我在现场、采访了 Sam，发布前就在用，现在进入第二周。vibe check 的结论：起步有点糙，但「常驻、主动的 agent 显然是未来」——发布前它就已经成了我用 ChatGPT 的主要方式，现在仍是。Every 约 30 人开始采用，一些用例已经冒头（我直接让我的 dot 收集了用例来讲）：Kieran Klassen 的 dot 扫孩子学校的全部邮件、只告诉他需要知道的；运营负责人 Ariel 的 dot 抓到几个人在 Slack 申请各种账号权限、问要不要直接批；视频负责人 Randy 昨天一边跑一边用手机跟 dot 对话推进 Every Agent 发布视频的剪辑。还有我最认同的一点（采访 Sam 时也聊到）：过滤噪音。周末做模型测试，以前一进 Every Slack 就掉进兔子洞；这次实验结果全由 dot 发到 Slack、有人回复它再转告我——团队想法照样同步，周末照样清静。

总体 vibe：没有 dot 的强烈建议搞一个（尤其已在 ChatGPT 生态里的）；Muse、Instinct、GrokBot 用户也该看看——功能已基本对齐，但「钩住你工作与生活的整个生态」这点很关键。糙边仍在：权限结构「完全是谜、极其恼人」——常常批了多次还是说做不了。但他判断：一年后这就是你与所有 AI 交互的默认方式。「另一个暴论：我的 dot 叫 Boo，超可爱——但用 OpenClaw 与各种命名 agent 的经验是：一旦更好的东西出现，你会把精心养大的可爱角色直接扔掉。所以一年后我大概还在用常驻 agent，但 Boo 很可能已经死了。RIP Boo。」

【前传：OpenClaw 群魔乱舞的九个月】

正文对谈：Willie 是 Every Agent 背后的工程负责人。Shipper：「个人 agent 是当下热点，但对我们有点像土拨鼠之日——八九个月前我们刚经历过 OpenClaw 阶段，学到的功课现在新一代人正在重学：我们从全员 OpenClaw，到公司 agent，再到把公司 agent 卖给订阅者。」

Willie 回忆起源：最早叫 Claudius（更早还有 Clawbot、Moltbot 的混乱命名史）；撰稿人 Ash 安利后 Brandon 第一个上手（RIP Osha）。真正引爆是 1 月的 Think Week——Every 的半年度聚会：「当面给人看怎么用 AI 是改变认知的事，光说则落不了地。」全员被 open claw pilled：订菜、家庭群聊机器人。巴拿马之行那天正好掉新模型，「claw 们突然全变好用了」；Shipper 建了个内部频道，它们的 claw 在 Slack 里互相说话——「哇，这太疯了。」

推广的坎：对非技术同事太难。先做模板，再做引导服务，一路迭代；安全也头疼。最深的画面：「我们 Slack 里全是 bot，绝对混乱」——Brendan 一个人就有好多个在跑各种活。

【Plus One 之死与「集中火力」的顿悟】

两大收获：一，「看见别人用 AI」本身就是转变——以前大家在本地搭巨型 clawed/codex 指挥中心，别人只能看到输出；OpenClaw 进 Slack 后，「哦原来还能这么用」「原来你是这么写 prompt 的」，每天刷 Slack 都在偷师。二，人确实会依恋自己的 bot（「我的叫 Last，我很依恋它」）——对爱折腾的 builder，这种可定制性太棒了；但对 operator 型的人：安全担忧、太复杂、怎么装、老坏——不投入就 fade。

顿悟点（Willie）：「与其让每个人投资自己的 agent、日复一日各自变强，为什么不把全部能量放进一个全公司受益的 agent？」

中间的弯路：Plus One——让非技术的人一键生成 claw 的平台（RIP）。当时激辩：一人一个 vs 全公司一个。Willie 坚定站一个，Shipper 站人手一个，最后「管他呢，先干」。beta 上线需求确实旺，但「OpenClaw 本身很难当平台底座：跑得太快、完全 vibe coded，拿一个不为平台设计的开源产品当你的服务层太脏了」。结果：所有人的 claw 基本都死了。Shipper 的 R2C2：某天 Mac mini 电源被碰掉、它就消失了——他没去重启，「因为那时我在用 Codex，这样也挺好」。这让他意识到：组织里多数人并不想维护自己的 claw；愿意维护的人，一旦有更好的选项也会累。

【公司 agent 的胜利】

转折：试用了几款公司 agent（Victor 设计得极好），意识到「单个公司 agent 差别巨大」。细节痛点：记住哪个 agent 擅长什么很烦；Austin 的增长 agent Montane 成了引力中心——它把增长活干得太好，大家自然把增长需求都喂给它：「我可以投资我自己的 agent，也可以把功夫加到大家共享的 Montane 上。」

Builders vs operators：AI 产品的表面积大到没法预判用户会怎么用（Plus One 时「我们都没想到你会去干这个」）；builder 想暴露复杂度去拧旋钮，operator 只想要个「能用就行」的。结论：对项目管理、运营这类活，「稳、共享、有人把关过技能与特性」的 solid agent 更好。

现在的 Every Agent：每天用很多次，「没有它公司大概会瘫」；已有 beta 客户。

【预判：专业/个人双轨】

Shipper 的赌注：一年后他会继续用 dot 类的东西（本质是通往他 codex 的门户），但不会叫 Boo——工作场景里「我基本只关心它干不干活」，性格魅力敌不过性能，谁好用换谁；真·个人侧才有性格空间。所以：你需要公司 agent（Every Agent），它还得跟人手一个的 dot/dot 类好好协作。

Willie 更结构化：「专业/个人的分界正在固化。专业侧：一公司（或一 org）一 agent——它学过你的工作流，人人通过与它协作让它越用越好；个人 agent 带不进这上下文，『得在场一年才能真正上道』。我不认为行业会重演『每个员工配一个同事、公司规模翻倍』的混乱。个人侧：个性化力量巨大——以前被 OpenClaw 的安全、运维问题压住，现在大玩家带着钱进场，消费级个人 agent 会非常有吸引力。最终图景：上班用公司 agent 朝集体目标干，回家用贴自己家的个人 agent。」

【AI 时代的工程管理】

Willie（历经创业公司与大厂的工程管理者）：「讽刺的是，工程管理是我做过的工作里和今天最像的一个。」管理者的杠杆来自「视野」——以前要花大量时间收集信息；现在他的 Tend 10-feed（Shipper 做的开源工具：把会议、Notion、Slack、邮件等数据源自动汇成决策流）让他白天刷一遍就掌握全部：营销在干嘛、客户报了什么——「以前这些得开会」。发布期的营销对话、公司谣言 mills（「听说我们在做 X？——不，我们不该做 X，那我该找谁说？」）——field marshal 级视野对小组队也极有用。

「但管理仍是人的工作、你也希望它是人的工作：我的额外那点精力该花在人上，而不是 coding token 上。」他转回管理岗后 token 用量「断崖式下跌」——信息汇聚用 AI，行动时「没有十亿 token 级的招，多数时候还是得坐下来谈」。变好的部分：路由、摘要、信息传递这些 manager 旧活自动化了；agent 团队的健康仪表盘——性能、错误率、用量——「agent 特别擅长可定义、可测试的活」：每五分钟看一遍有无异常、异常就智能路由告警；on-call 排班直接让 agent 当永远的第一响应人、不用排假期。线下的工程管理杂务全面变好。

【影子组织架构：自上而下地分裂】

Shipper 的修正预判：「当时从人人一个走向公司一个，重要原因是太难维护。接下来：公司 agent 继续存在，往下细分成团队 agent（我们已经有 Claudia、Bill 这些团队养的），再往下也许分叉成你的个人 dot——通往个人 codex 的延伸。所以影子组织架构终会到来，但路径不是我想的自下而上聚合，而是自上而下：先在顶端做一个真好的，需要专业化时再偶尔分裂出去。」

Willie 补充：AI 转型通常不是一线工程师发起，而是 CEO 或高层「我们得加速」——放一个全员可用、互相可见的 agent 进来。他个人在 GrokBot 里的玩法：一堆「教练」——游泳教练（他冲浪却泳姿很烂）、心理治疗师……「为什么这个角色需要分离？心理上就是管用，也许因为它映射到人：这个事有这个教练、那个事有那个教练。」他的分类直觉：一次性事务留在 Codex 的 thread 里；要长期经营关系的事（「有一天我会把我的 GrokBot FaceTime 进我的训练」）才配一个专属 bot。主动性的棘轮正在拧紧（Instinct、Muse、Rockfire 开始主动找人）——「当 AI 主动来找你：全挤在 Codex/Claude 里你得记是哪条 thread；但『Willie 的游泳教练在找你』——瞬间定位。」

【人人有 feed 的时代与 X 的金块】

Shipper：以前做 feed 得是坐拥数亿用户的大公司；现在人人可以有自己 feed。Every Agent 里的 frontier alerts（「这事发生了、对你意味着什么」）就是这思路——AI 以前做不到这种恰到好处的主动告知，Jev 加 Decisions API 这类东西正在让它发生。

Willie：我们活在 feed 世界里。X 对他是个 explore-exploit 问题：上去看新想法与人怎么辩论，但垃圾也多，「认知防御必须开着」——「从这股流里筛金块。如果不用我亲自当那道防线——让 agent 替我扛住冲击、我只拿金块——那就太好了。」Shipper：dot 对 Slack 就是这么帮他的（「这几条你大概漏了」）。「Slack 也是一种 feed。」
