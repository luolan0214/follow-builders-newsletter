English

Rauchg's Ouija post (169): 'Agents can play "Ouija" in the cloud. This class of timing attacks on shared-host VMs has been known since at least 2015, with no full solution. The world's cyber infrastructure runs on "yes, that attack is theoretically possible, but who would have the ingenuity & gall to go that far!" Enter, agents. I'd describe this particular OpenAI find as a "noisy neighbor" attack. If two agents are on the same machine, one can make enough noise (through the CPU caches!) that the other one can detect it by timing its own computation and cache accesses. The only "complete" solution would be dedicated hardware per agent, which has significant economic consequences. For Vercel Sandbox, we've deployed every practical mitigation possible, complemented by always-on monitoring and red-teaming.' Levie's swarm thesis (358): 'Agent swarms for cyber defense is about to be one of the biggest categories in AI… Security is one of the best use-cases for swarms because it's an obvious area where more compute in equals more value out. There's a wide range of testing that people can never get around to — or at least quickly enough — that agents have no problem going after. Going to be a wild time in cyber.' 本刊首次收录 No Priors：对话 Cloudflare CTO Dane Knecht——为 agentic 网络普及安全。核心线索：漏洞末日（CVE 报告指数级上升、Log4j 级事件从每年一次变成每周一次、超过 50% 工程时间花在安全上——「未来 18 个月多数团队时间都会耗在安全上……某时刻 AI 会把大多数代码扫完、把大多数 bug 找光」）；都市传说成真（保护全部 TLS/WebPKI 的密钥种子是数字 4；OpenAI 找出 2000 年 NIST 曲线种子；「不只是模型变强、是 harness 变强」）；攻击者画像（不是国家级行为者而是高中生「agent kitties」）；关于「把一切都物理隔离」（「我没那么末日：人类适应力很强、危机时刻竞争者不再是竞争者」）；工程答案（缩小攻击面——「AI 很啰嗦、爱造复杂度，眼下其实没帮上安全的忙」；内部 Codex 文档浓缩成 agent 在评审中执行的十诫；红队从 1 个扩到 4-5 个）；agentic 网络经济学（人类与 agent 同轨的「乱纪元」、人网/机网分离、agent 按 CPM 付费的微支付轨道——Cloudflare 内容变现网关、agent 钱包、稳定币、与 OpenAI 的 signals 项目、Stripe 复活 HTTP 402 的 X402）；Cloudflare OS 内部平台与 5 月 AI-first 重组（邮件流程从三个团队变一个工具）；token 预算哲学（「让人类决定每个任务用哪个模型挺傻的——应该智能路由」；不搞 token 排行榜、只发温柔提醒：300 美元/天邮件你、500 抄送经理、1000 上报 VP）；五千人公司招一千实习生的战略；agents@cloudflare 别名后其实是一群实习生在写 skill 文件；招聘看好奇心（「家里不用 AI 是个相当大的红旗」）；开放模型与网络（「最终会开放，因为反正人人都会拿到」）；以及给雇不起四个红队的所有人的答案：把站点放到 Cloudflare 后面——React 漏洞的缓解给了所有人。「把安全与性能民主化，给每一个人。」完整译文见下。

【开场：从『让大家用 AI』到『搞清 AI 安全』】

Dane Knecht（冷开场）：AI 成了造成这场安全末日（apocalypse）的工具，同时也是能帮我们更快解决它的工具。过去一年从「怎么让所有人用上 AI」，突然变成所有人都在抢着搞清楚「AI 安全」意味着什么。

主持人：十五年来头一次，我听到严肃的技术人说「把重要的东西都物理隔离吧」「我们会有一阵子没法信任互联网」「我们就假设所有关键基建与政府服务某天会瘫痪」。这是你的预期吗？另外必须说：你姓 Knecht（谐音 connect），跟 Cloudflare 的价值主张真是绝配。

Dane：哈哈，明年改名的事已经开过玩笑了。说回正题：这一年像十年压成一年，但一切回到使命——帮互联网变得更好，十五年来没变过：让互联网安全、人人都能轻松上线内容并扩容。过去一年的 AI 变化：从「怎么让所有人用上 AI、让他们的 agent 顺利部署」——和多数技术迁移一样，安全是事后才想的事——到突然所有人都在搞 AI 安全。而且各方看法不同：作为企业，一头是怎么防止 AI 把数据漏出去，另一头是怎么防止别人进来。

【漏洞末日：每周一次 Log4j】

Dane：过去三到六个月，CVE 里报告的漏洞数量指数级上升。以前互联网上一年才有一次 Log4j 或 Shellshock 级的事件——Cloudflare 内部全员上阵，保护企业客户、也保护全部免费客户（我们把这当公共品）。现在这些事每周都在发生——不是都见报，但严重程度与 Log4j 相当、频率高得多。我预计今年剩余时间到明年、这 18 个月里，多数团队的主要时间会花在安全上。今天 keynote 上有个统计：超过 50% 的工程时间将花在安全上。我不认为这会永远持续——这是一个短促的过渡期：某时刻 AI 会把大多数代码扫完、把大多数 bug 与捷径找光。

今天就有一个正在被报道的：互联网上一把保护全部 TLS 与 WebPKI（保障你所有连接安全）的密钥，它的种子是数字 4。字面意义的 4。懂密码学的都知道一切在于随机性——这也是为什么我们机房要摆一排熔岩灯（为了好随机数）。而用单个数字 4 做种子的密钥会被逆出来。AI 干这些活不睡觉——不是从前那个只有一名红队工程师的时代了。上周 OpenAI 还找出了 2000 年发布的 NIST 曲线的种子。一切都在加速，门槛在升、模型在网安上突飞猛进——Midtest 只是冰山一角：此后不只是模型更强，是 harness 更强——是人类学会了怎么用这些前沿模型找漏洞。

【Agent Kitties：攻击者画像】

主持人：凭你的可见度，这些把漏洞发现量推上去的人是谁？国家级行为者？脚本小子？

Dane：有意思的是，近期几个大漏洞的发现者其实不是国家行为者——有些甚至是高中生。就像过去打 CTF（夺旗赛）那样，把自己的 agent 指向一个领域去挖。而且有经济回报：bug bounty 的奖金相当可观。等于把国家们早就有的工具（不管是 agent 还是单纯堆人力）交给了大众。

主持人：那以后我们该叫他们 agent kitties（agent 小子）了。

【物理隔离论与零信任】

主持人：十五年来我头一次听严肃技术人说「把重要的一切都 air gap、有一阵子没法信任互联网」。这是你的预期吗？

Dane：人类适应力很强、需要时跑得很快；我也见过行业在危机时刻真正联手——平时是竞争对手的公司不再是竞争对手，大家就是在保护关键基建。所以我没有那么末日。而且过去五到十年从「城堡护城河」转向零信任的迁移，让很多公司处在了更好的位置：等于在说「这个办公室已完全隔离、这些设备与数据流以另一种方式加固」——一切都会收紧。

主持人：上周 Greg Brockman 在这个节目里说，2027 年人们在安全上花的 token 钱会跟工程一样多。什么会驱动这个转变？

Dane：紧急事态本身。未来 18 个月你会把安全支出（红队侧的进攻性测试 + 防御侧的准备）全部提前。但不会永远这样：我看到一个 18 个月后的世界——新软件生产力大幅回升，因为这些资源重新聚焦回生产。但确实有这么一段「人人都想着安全」的时期。

【补 70 年的课与缩小攻击面】

主持人：还有什么关键？毕竟软件生产速度也在暴涨——既要补存量、还要追平增量。

Dane：我们此刻是在给七十年的软件打补丁，一部分纯属还债。往前看，软件开发生命周期、agent 开发生命周期都得变。幸运的是，就像我们现在能拿 AI 做红队一样，安全会被内建到流程每一步。我认为软件会随时间变得更安全。

从第一性原理讲：你要缩小攻击面。最简单的一招：减少可能出漏洞的地方——审视全部软件问「怎么简化？怎么缩小代码足迹？」之后才是形式化验证、更安全的编程语言、运行时内建安全。但有一点：早期 AI 非常啰嗦、爱造复杂度——就我们处理的来看，AI 眼下其实并没有帮上「造更安全的东西」的忙。我认为会走到那一步，但这正是人类与人类判断仍然要进场的地方：确保软件设计得能自己站稳。

主持人：那正是我要说的——「减少表面积」当然对，但今天的模型天生不是这个倾向。我说「请用十分之一的复杂度重做一遍」。这是今天工程师的角色，还是会在模型层解决？

Dane：像 agent 出现之前人类做的那样：每一层都要解决。要训练写代码的产品工程师；安全团队仍要做制衡、当第二双眼睛；要建流程。我们在 Cloudflare 把做法大量写了下来：内部有一份叫 Codex 的文档——一堆 RFC 的沉淀：「在 Cloudflare 怎么造安全的软件」「怎么造高可用软件」「我们的最佳实践」，然后浓缩成十诫（ten commandments），agent 知道怎么在评审的每一环遵循并执行。所以外面有一堆 agent 在写 slop（水货代码），工厂更深处有人在跑性能与安全测试——跟以前一样，需要对抗性的评审。

【乱纪元：人网与机网分家】

主持人：看整体流量——过去一年 agent 流量远超预期。你对一年后的网络世界观有什么更新？

Dane：我们处在「乱纪元」（messy middle）：人类和 agent 跑在同一条轨道上。agent 在解析一张为人类设计的网——低效、速度不同：人访问一个网站、看广告、参与完整经济模型；agent 同期可以访问一千个网页——很好，但你需要新的经济模型来支撑。会有并行网络吗？人网和机网？

我认为会有。我们会找到把内容分别递送给 agent 与人类的方式，而不是逼他们在同一处相会。现在有翻译层——一堆公司帮 agent「看」网页——这些其实都是在白白烧 token。网站自己知道有什么数据。我们早就有 API（计算机互谈的方式），但 API 只覆盖了互联网信息的一小部分，而 agent 渴望理解一切——所以它们出去探索人类互联网。我们要让它们更容易拿到、让站长成本更低、让它们有办法获得补偿。

拿一个好的内容网站（比如 Substack）举例：站长知道自己的 CPM（广告千次展示收入）。如果 agent 来读站，我认为会有这样一个世界：agent 可以先决定要不要读这份内容、然后决定要不要按 CPM 价格付费。这就需要互联网的新支付轨道：每秒百万笔的微支付。微支付谈了那么多年、永远「还差两年」——我认为 agent 会真正把它推到位，内容创作者会有新的经济模型。

【X402、signals 与内容变现网关】

主持人：这基础设施的玩家是谁？Cloudflare 显然有角色，但 Instinct、Muse 这些个人 agent 让交易问题变得迫在眉睫。

Dane：另一头的人其实还不知道商业结局长什么样。大家经历过「互联网杀死主街」的预言——主街没死、小生意活得很好，但确实有人被取代，所以天然有怀疑，于是天然倾向直接封掉——Amazon 就刚说了不允许 agent 个人购物。这些都是乱纪元里还想保住谈判筹码的玩家。我认为我们终会走到 Muse、Dots 这些个人 agent 无缝完成任务的世界——甚至比人类更容易。只是技术还没跟上，商业模式也还没有。

Cloudflare 在做的：内容侧我们发布了内容变现网关（content monetization gateway）——让站长轻松把站点放到我们后面、对内容收微交易；包括给 agent 用的钱包、一个稳定币来促成交易。我们也在和 OpenAI 做一个叫 signals 的项目：让 agent 更容易发现内容，而不是爬整个互联网、反复回访同一页面——更容易知道什么是新内容、更主动地拿。这对 AI 实验室是赢、对站长也是赢（不用被反复爬、付那些基础设施的钱）。互联网的一整套新轨道在长出来，我特别兴奋：比如 Stripe 发的 X402——我爱它因为它回到了 HTTP 402 状态码，那是 Tim Berners-Lee 三十多年前为支付准备的。你一直都知道互联网需要更好的支付轨道，只是一直没搞定——我认为 agent 会把我们带到那。

主持人：对靠广告变现的站长，什么样才算杀手级成功案例？

Dane：关键区别：不是他们付我们钱，是我们付他们钱。覆盖他们的基础设施成本、给支撑生计的钱——我们能实际增加内容创作者的数量。上一代互联网（YouTube、TikTok）做得很好，这次能把它再放大一个量级。

【Cloudflare OS：内部 AI 平台】

主持人：Workspace OS / Cloudflare OS 是什么？

Dane：Cloudflare OS 是我们的内部平台：员工每天怎么用 AI。它其实源于安全：我们非常担心客户数据、内部数据外泄，想让员工能用上所有新 AI 工具与模型、但有一种安全部署的方式——知道数据怎么被使用怎么流动、有治理。叫「OS」还有个原因：agent 越来越多，我们得教会它们「Cloudflare 特别在哪、我们怎么造东西」。对人类我们靠 Cloudflare 大学、入职流程、跟同事共事；对 agent 我们需要把这一切更清晰地定义、写下来。所以 Cloudflare OS 既是员工随便造东西的安全平台（安全内建、不用自己操心——那个想建呼叫清单的 BD 不用担心安全），又保证做法与「软件在 Cloudflare 怎么运作」的价值观一致。

为什么发布？某种意义上它是参考架构：过去十年我们从单个 serverless 原语建起开发者平台、如今上百种工具（存储、数据库、Durable Objects）——我们想展示怎么完全建在 Cloudflare 上、我们内部怎么造，大家可以 fork 去造自己公司的 OS。

成效上有个反直觉的发现：用得最多的不是工程，是 GTM（销售市场）与 G&A（行政财务）。早期我们以为培训是最大缺口——把人丢到聊天界面，白板一片太吓人。这个平台一切都按你的业务设计好，进去就能拿到需要的全部数据、被引导着走——他们很快意识到「这不是要取代我、是让我更擅长我的工作」。营销团队用它造了几百个内部工具——以前要找代理商，现在小团队就能跑出惊人的速度。

【五月重组：工厂地板式重造】

主持人：延续今年五月那场 AI-first 重组——复盘哪些成了哪些没成？

Dane：重组很难、告别了一些同事——Cloudflare 史上第一次，以前一直小心不超额招聘。这次原因不同：我们看见 AI 正在改变一些团队的工作方式。把它想象成工厂地板：你需要真正重建、重想流程。比如产品发明者给客户发一封邮件，以前要过三个团队：去 BI 拿目标人群名单、去营销团队设计与调语气、去营销运营团队发出去。你不做硬改变、逼大家重想，就永远没法重造这个流程——也许根本不需要那三个团队。产出的工具现在是：产品经理进去描述人群、写邮件、系统用 Cloudflare 的语气重写、发给经理、经理点批准就发出。我们不是让三个团队变快——是变成了一个工具，让产品经理拥有从前没有的超能力。

主持人：五千人的公司，谁拥有「重想流程」这件事？

Dane：Cloudflare 永远有一千件想做的事，我们永远找主动拿所有权的人。排序不重要——那一百件事里只要有人真正有热情，做哪件都安全。所以去年初我们把工具发下去、看大家怎么实验，人很快分了层：真正扑进去、自然拿走所有权的那批。所以非常自下而上。

【token 预算哲学：智能路由 + 温柔提醒】

主持人：组织里怎么想 token 预算？

Dane：一直在变，每个新模型的成本结构都让你重想。但总的来说：让人类决定每个任务用哪个模型，这件事挺傻的。

主持人：应该智能路由。

Dane：对，人类永远不擅长这个。早期我们蛮力地试：规划阶段用顶级前沿模型；计划写好、迭代定稿后，执行可以交给更开源的模型；再回到前沿模型做评审与红队。今天这些都还挺手动，但随着学习实验，会越来越智能、有治理。Cloudflare 基本让大家自选模型与工具：我们不搞 token 排行榜、也不鼓励——我们鼓励关注产出：不考核你用没用，考核你交付了什么。但我们做了温柔提醒：一天用掉 300 美元会收到一封邮件「你知道吗……」——多数时候人们根本没意识到；到 500 通知你经理；到 1000 上报 VP。这种事很少发生，而且大家其实挺乐意收到提醒。

【一千实习生战略】

主持人：以当前模型能力为限，你们走到哪一步了？

Dane：还非常早。两年前我们招了约 200 名实习生，发现他们是第一批真正的 AI 原生代——把 AI 从他们那拿走，他们大概没法工作。

主持人：这是好事吗？

Dane：我认为是。他们比我们更会用这些工具——就像过去十年你把 Google 从我这拿走、我还怎么学东西？他们伸手第一件事就是它。而且我们观察到：带过实习生的经理采用 AI 更快。所以今年我们决定招一千名实习生。

主持人：五千人的公司？

Dane：对，全年滚动。效果惊人：一是点子多——AI 让更少的人更快实验，人多点子多；二是看他们用 AI 的方式：要填个表？直接用 AI。我自己到现在还经常「咦这事我一直在手动做」——哦对，应该用 AI。这对我们大多数人还不自然，需要时间。所以我们连 AI 之旅的门都还没进。

Waterloo、Northeastern 这些 co-op 项目出来的人，有真实工作经验，多年后往往是我们最好的员工。另外一个彩蛋：今年一月我们搞了个邮箱别名 agents@cloudflare——告诉员工「好奇这事能不能用 AI？把你要办的事发邮件过来」，这个邮箱会回你一份 skill 文件。有一阵子大家以为全是 AI 自动化的——其实是一群实习生在帮大家写 skill 文件。这让我们不用请咨询公司来编目全部工作，就看到大家在哪些地方觉得「这事比它该有的难度难」。

【招聘：家里不用 AI 是红旗】

主持人：过去一年你的招聘哲学变了吗？

Dane：我们最看重的一直是好奇心。一个人在家、在个人生活里完全不用 AI——那是相当大的红旗。有一定好奇心的人怎么会不拥抱 AI？所以驱动力、好奇心、同理心这些特质，对下一批人更加分。我们在做的事多数没有现成技术：以我们的规模（背后的站点数、免费的量）不买现成就能跑——需要能进来真正发明新东西的人，而发明始于好奇。

【红队扩编与「不发货就死」】

主持人：收尾几个安全追问：一半工程团队去补七十年漏洞，内部怎么攻？

Dane：我们现在有一个红队；到年底明年会有四五个红队——分组、更对抗性地主动找漏洞。

主持人：为什么是这条路，而不是「终于把补丁流程弄完美」？

Dane：流程永远可以更好，我们有漏洞流程、补丁流程——完美吗？不。但当量大到常规流程处理不过来时，工程师天然「懒」（好的那种懒）——他们会把它自动化掉。危机逼出自动化。所以重心放在发现侧，补丁侧人们自然会找到可规模化的路。

主持人：安全 vs 发新功能，怎么排优先级？

Dane：两边都要做。可能牺牲的是成本优化之类。但公司不发货就是死——我们从不冻结发布。做对了的话，AI 反而让两件事都更快：AI 是造成这场漏洞末日的工具，也是帮我们更快解决它的工具——两边都是它。

【开放模型与「给所有人的安全」】

主持人：网络安全上开放与闭源模型之争，你站哪边？

Dane：我认为长期会走向开放，因为反正所有人最终都会拿到。坏人总会找到办法，顶级公司们也总有办法——你只是把一大群真正需要它的人排除在外。

主持人：最后一个问题：那些雇不起四个红队、从来就没有过红队、却运行着重要系统的人怎么办？

Dane：把你的站点放到 Cloudflare 后面、把保护建在 Cloudflare 上。遇到大漏洞（比如去年的 React 那个），我们不是只给买了高级防火墙与 WAF 的付费客户——我们给所有人。我们把这些当作公共事业的一部分，就像我们为所有人提供性能。Cloudflare 出现前，世界上大约只有 3000 个站点有大规模 CDN 在边缘缓存；现在有数亿个。我们一贯的目标就是把安全与性能民主化，给每一个人。

主持人：完美收尾。你们先听到的：agent kitties 与漏洞末日（Vulnkapocalypse）——但它是可解的。谢谢 Dane。
