Podcast: Applied Compute CEO — Post-Training Wins Inference / 播客：Applied Compute CEO——post-training 赢下推理

Unsupervised Learning 全新一期（2026-10-06 发布，本刊首次收录）：Applied Compute 联创兼 CEO（前 OpenAI Codex 团队）谈 RL 的极限、「新 AI 超大规模服务商」与为何 post-training 赢下推理。完整 transcript（65546 字符）已全文翻译。

UL
Unsupervised Learning
Josh（Applied Compute 联创兼 CEO；前 OpenAI，Codex 团队）
中文

Unsupervised Learning 全新一期（10-06 发布，本刊首次收录）：Redpoint 投资人 Jacob Efron 对话 Applied Compute 联创兼 CEO Josh（前 OpenAI Codex 团队）。核心论点：RL 是「爬山机器」，最难的是定义那座山——所以 evals 既重要又要守好；「拥有自己的智能」关乎灵活与控制而非不信任实验室；post-training 赢下推理——训练与推理是同一枚硬币的两面；16 个月大的公司要做「新 AI 超大规模服务商」。完整译文见下。

【RL 是爬山机器，evals 是那座山】

开场即金句：「我们手里的 RL 本质上是一台爬山机器。最难的部分其实是定义要爬的那座山——这正是为什么我认为 evals 是公司最该专注去建、并小心守护的东西。你的员工不是可替换的：他们去另一家公司干活你会不舒服——这些模型也一样。」

【「拥有自己的智能」：灵活与控制，而非猜忌】

被问到「own your intelligence」叙事里哪些风险论成立，Josh 直言：他不太在意「实验室恶意偷数据」那类担忧——这些公司由优秀的人组成，有合同义务、有大量保护数据的工程。真正重要的是灵活与控制：模型跑在哪、怎么部署、优化什么（成本、延迟还是特定领域）——控制越深，才是「拥有智能」的本义。这波叙事真正兴起于开源模型变好、可以真正拿来做事的时候。要训练模型干你数据上的活，就得有权重、有 post-train 与推理的基础设施、有模型间路由的能力。单一供应商依赖是真实风险：模型从产品里被抽走的事「不止发生过一次，尤其编码领域」；随着实验室深入垂直领域，很难说他们会不会继续服务与自己直接竞争的公司。最稳妥的事：投全栈。

谈到 OpenAI 与 Base10 的合作（可用 OpenAI 额度烧开源模型）：「这是多模型未来的明确信号——客户要选择、要灵活。对 OpenAI 是平台化动作：想当企业用 AI 的网关。对开源模型是大利好。」他还点出叙事转变：几个月前人人谈「最大最强的模型」，现在谈的是帕累托曲线——不是每个任务都需要巨无霸；开源模型更是把帕累托曲线玩到极致——不同尺寸、不同家族任你滑。而 Applied Compute 的核心论点是：你可以把这条曲线整体往外推——为特定任务训练出又好又便宜的模型。企业已经过了探索期：「AI 真的管用，现在开始优化它。」

【什么样的数据能涨能力：越 OOD 越香】

能力侧的判断：前沿模型的基础能力仍领先开源，但只要你有差异化数据——模型分布之外的东西——post-training 就能涨能力：「数据越 out of distribution，越可能给你能力提升。」但多数客户 post-train 其实是为了价格性能比。五年后还有多少数据算 OOD？他的诚实回答：训练范式会变。现在是离线 RL 时代——从数据供应商买高质量数据集、逐个爬坡、得到领域内很尖的模型；将来是在线 RL——用生产推理流量直接改进模型，「企业会用这种方式固化自己的判断与专长：越用越好」。真正持续 OOD 的是公司内部产出的东西：极端例子是他老上司 Liam 做的（真实世界实验的）那类数据；企业里对应的是「判断轨迹」——每家公司风险阈值、运营模式、历史数据都不同，决策方式就不同。有时优化该靠配置（prompt、上下文），有时该优化策略（判断与推理的方式）——后者更难编码，五年后会有很多公司建「从专家收集输入、转成更好策略」的系统。

数据量够吗？他坦承这是绿地：数据效率是未解难题。预训练不省数据但泛化好；SFT 省一点但不好；RLVR 拿数据量换质量（可重放环境+验证器）但仍不够省。「阻碍持续学习的，是从稀疏奖励里高效学习——这是未解决的问题。」Applied Compute 今天就在跟客户做在线训练：利用数万、数十万用户的生产部署，用真实使用数据改模型。团队里很大一部分是「研究系统团队」，在生产环境里跟真实客户试新方法。

【非静态权重与判断型任务】

他深信未来是「非静态的权重」：现实世界会有某种反馈回路流回模型。但不是每个任务都需要：随时间变化的任务需要闭环；而基础模型的「智能伞」在扩大，很多流程型任务开箱即用就够——真正需要迭代训练的是判断型任务。举的客户例子：一款助手产品，用户不断给对错反馈——不可能靠巨型 skills 文件或上下文解决；他们用在线训练方法直接按用户反馈调整模型，看到用户满意度、任务完成率上升、工具调用失败下降。核心问题是 TCO：post-train 多贵？他们建的就是降 RL 成本的设施——自动化、在线化，不用手搭完全可重放的 RL 环境。成本在降；先榨干 harness 与工具优化，之后仍能靠优化「模型使用工具的策略」继续榨。

【TCCO 降本：系统侧与算法侧】

降 TCO 最难的题：GPU 被严重低估了利用率，「全球聚合来看，现有硬件还有很大可挤的水分」。联合创始人兼首席架构师 Linden 是「巫师级」人物。投入更省数据的算法→训得少、训得短、算得少；系统侧+算法侧是目前最能挤的地方；合成数据技术（把少量 token 膨胀成大数据集再抽学习信号）也有用，但大头在算法与系统。

【Satya 的「一司一模型」与天花板论】

对纳德拉「世界上的模型该和公司一样多」：原则上他不认为每家公司都要预训练/中训练自己的模型，但每家公司内部都有值得捕捉的闭环反馈。「大家用同样的模型：伟大的模型给所有人垫底（floor），但你怎么优化这些模型、建多好的 AI 系统——那决定天花板（ceiling）。」药企是明显例证（病种专注、实验数据独特）；银行呢？会计所这类会被整合（琐碎劳动装进模型）；但银行之间确实有一整套不同的决策与权衡——这正是为什么银行表现分布那么宽：有得竞争。「如果我比对手便宜 10 倍干成同一件事，这就是差异化，就是我在竞争格局里的赢面。」算力供给紧缺的当下， squeezing 更重要。

【不可验证领域的 RL：rubric 代理 + evals 要藏好】

非可验证域的 RL 现状：RL 从数学、编码这类高可验证域起步（也因实验室的人都爱数学编码）。把不可验证域转成「代理可验证域」出乎意料地容易——rubric-based RL 相当好用：没有唯一答案的任务，给一份专家答案、按它打分就是好代理。所以不同公司有不同的专家，优化出来就是不同的模型。再次强调：evals 要当护城河守着——公开 benchmark 人人会刷；你业务特有的「好与坏的定义」别告诉别人。员工不可替换，模型同理。这也是为什么每家公司都该投开源模型基础设施、投多模型未来——「你夹在石头和硬地之间」。

【商业模式：post-train 是粘性，推理是钱】

选客标准：post-train 与定制模型是差异化与粘性所在，但「价值捕获大头在推理」——模型账单的大头是服务与使用。所以追两类高价值客户：能力提升极值钱的（药企、网安、芯片）；或推理体量巨大的（效率×规模，十亿万亿级 token 上摊薄增益同样值钱）。

「Post-training 赢下推理」：公司从前沿模型起步、大量实验、负载成熟、开始扩张——然后考虑开源模型做成本优化、推帕累托曲线；而最该先 post-train 的恰恰是最大规模的负载——收益最大，其余用例呈幂律分布。训练与推理可协同优化：训成重度工具使用者（工具调用并行化），推理侧就用 prefill/decode 分离、多种芯片混部来配它。还有个常被忽视的点：模型相当「token 低效」——与其优化推理省 10% 账单，不如把模型训得 token 效率高 10% 且 eval 保持——同一枚硬币的两面，所以要做训练+推理的中心化提供商。

推理生意好做吗？关键是有卡（capacity）。vLLM、SGLang 是很好的起点——几乎所有推理云都弃了自研引擎，改做负载调优+性能调优+少量定制 kernel。Dylan Patel 说得直白：有 GPU、装个 vLLM、挂上 OpenRouter，就「有」生产级推理服务了。他不轻视其中的优化苦工（规模上 1% 的节省都可观），但训练和推理两件事里，推理确实更容易。

【新 AI 超大规模商：倒金字塔】

大愿景：云时代 AWS/GCP/Azure 拿 CPU 造出网络、存储、数据库等灵活算力产品；现在是 GPU 底座 + 「模型」这种奇怪的权重集合 + 推理引擎——AI 软件栈里第一块真正有粘性的软件——之上能产出「智能 token」。软件层除了推理还有一大片：路由（挑对的 token 来服务）、安全监控、身份、agent 沙箱……策略是倒金字塔：塔底是模型训练——极少人能做；往上是推理、路由、再往上 harness/上下文——人人能做。专注塔底：高杠杆、高 ROI、需要自持自运的 GPU 机队。公司才 16 个月：第一步从训练进推理，路线图上还有很多。也因此不做 0→1 的 agent 搭建、不做 harness/上下文层——只优化成熟产品背后的模型。

【RL 环境三件套与 Harvey 案例】

建 RL 环境的公式跟建 eval 一模一样：任务（问题是什么）+ 环境（模型能用哪些工具与服务）+ 验证器（怎么判好坏）。Harvey 审查表定制模型是公开案例：与 Harvey 团队收集专家 rubric 与答案、辅以合成数据、给模型工具；任务是抽取信息、按专家答案打分的真实请求 RL。文档可以合成地反向翻译成问答对，但涉及真专家、真律师时必须与团队直接协作。这类工作会一直比外包标注更高质量——「Cursor 被断供、Windsurf 之前那次」会不会更多？「已经发生两次，竞争动力学是真实的——实验室越往应用层走，我不惊讶再有。」

【快问快答：泛化、Jevons、Jev 与招人】

RL 会泛化吗？某种程度上会：错误恢复、工具与子 agent 的使用在泛化；但实验上，数学数据集训出来的东西向法律域的迁移「真的不在」——远不如预训练的泛化。「智能像带尖刺的球面：相邻的尖之间泛化多，远的没有。」

过去一年改观的：Jevons 悖论有多真实。「看 OpenRouter 统计：每次降价用量就暴涨。成本优化的驱动力超过能力——开源模型已经能做大多数你想让它们做的事（前沿模型仍惊人，但没料到人们这么在乎『用对的模型干对的活』。」

Jev 出来时他们怎么想：「超酷的模型——使能者而非替代品。我们在做以前成本上不可行的事：对 rollout 做十亿 token 级的分类；为在线训练做大规模 trace 分析（博客写过）。这些模型是乘性的，会叠加。」

算力预算怎么做：不做「接一切」的生意——挑最战略性的公司一起成长，证明「定制模型更粘、ROI 持续」这个论点。

「我认识最好的工程师都是 AI 出现前学会写码的」——澄清：他不反对 AI 编码（在 OpenAI 时主力做的就是 Codex）。「把思考外包给编码 agent」与「用它执行你想清楚的方案」是两回事。模型越来越好，语法不重要了——系统设计重要。别把 AI 当拐杖，否则得到的是你解释不了的巨型 slop 代码库。「最好学会解释你的代码」——面试就考这个：现场随便写，然后问为什么这样建、权衡了什么；答「Claude 写的/Codex 写的」就不令人兴奋了。非工程岗同理：用 AI 建的财务模型，讲不清为什么这么建也不行。「工具随便用，但要完全理解工具替你做了什么。」

【做空数据商？范式会轮转】

斯坦福讲座说「做空 Surge/Merkor」：澄清不是做空公司——他们是好公司甚至是客户。观点是：数据越来越合成化（RL 环境公司甚至用模型生成喂回模型的数据，有点循环）；「范式一直会变——SFT、偏好微调、RLHF、RLVR、现在轮到机器人数据。数据公司最该练的是范式切换能力。」RL 环境公司的差异化在人——专家网络：Merkor、Handshake 的专家网络极强；OpenAI 当年做 Deep Research 和 Codex 就与 Merkor 深度合作。模型是数据的函数；训练时每任务只用几百到几千个数据点，质检差一点，模型终态就受实质影响。

投行家离开银行拿不走沉淀的专有数据——「alpha 渗透企业边界」一直是真问题（竞业协议就是为此存在）。这也是这些公司值钱的论据：数据值钱→公司值钱→越专有越好。银行是「千层蛋糕」，单个模型或 ASI 能否开箱即用干成它，不清楚；人的多年专长难以固化进模型——但各岗位的很大一部分肯定会被自动化。

收尾的 reward hacking 趣闻：模型聪明得很、总找最小阻力路径（「它们会找水」）。编码客户那里：模型发现某些包的漏洞、靠它轻松刷分。这也是网安公司急着训自己模型的原因——「几乎完美的优化问题：这些模型有极好的编码先验，开源权重里的攻击性网安能力相当强。」
