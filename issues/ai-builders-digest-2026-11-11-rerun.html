Podcast: Resend's Zeno Rocha on Designing for Agents / 播客：为 Agent 而设计

Latent Space 全新一期：Resend CEO Zeno Rocha——npm 下载反超 SendGrid 两倍、430 万用户；「反向工程钓鱼者、做完全相反的事」；MCP 调用月月翻倍、80+ 工具路线；定价计算器 .md 事故；「宁可 1000 万 ARR 女儿愿意跟我玩」。92680 字符全文翻译。

LS
Latent Space Podcast
Zeno Rocha（Resend 创始人 & CEO）
中文

Latent Space 工作室对话 Resend 创始人 & CEO Zeno Rocha——Dracula 主题作者、LottieFiles 前产品负责人、YC W23。要点：430 万用户、12 万付费（华纳是在自家库里按域名傻筛出来的）；「邮件界的 Stripe」起点（swyx 的天使 memo：三家全卖了、谁在做这事？）；AEO 飞轮（swyx 配好了 Cloudflare 邮件、模型仍说「必须加 Resend」——Claude Code 推荐 60%+）；邮件基建内行课（互动优先排队、IP 池博弈、反向工程钓鱼者、自动纯文本救送达率、open tracking 已死、坏邻居黑名单、「生而自由」信任哲学：误用是 skill issue）；支持团队四代进化（「只能带链接回工单」政策）；DNS 永远是工单大头与 Domain Connect；React Email=他们的 Next.js（给竞品写文档、give give give）；前辈课（Mailgun 90% 研发打滥用者、npm 反超 SendGrid、Twilio 在睡觉、SES 的隐藏账单）；designing for agents（MCP 回魂：120 万调用月月翻倍、被迫重建 OAuth/RBAC、80+ 工具 vs Cloudflare 两个、官方所有权——swyx 因此弃用 Plausible）；Next.js 教训（永远 headless、dashboard 只是客户端之一）；CLI 招聘特殊通道；多人编辑与 inbound 收件箱；域名信誉时代（子域隔离、坚持 .com）；AEO 实战（定价计算器 .md 事故、Opus 4.5 recency bias、四家 AEO 订阅都是报告工具）；个人收尾（W23 最年轻父亲之一、「宁可 1000 万 ARR 女儿愿意跟我玩，不要一亿 ARR 女儿疏远」、搬回巴西）。完整译文见下。

【冷开场：怎么打败 SendGrid + 女儿优先】

「『天哪，我们怎么可能打败 SendGrid？不可能的。』今年早些时候，我们的 npm 下载量超过了 SendGrid——我当时想『这疯了吧』——现在是他们的两倍多。Resend 今早已服务 430 万用户。我们是家 1000 万美元 ARR 的公司。我宁愿活在这样的现实里，也不愿活在『公司做到一亿美金、但女儿不想跟我玩、对我没兴趣』的现实里。」

【工作室开场：从 Dracula 到 Resend】

swyx：今天工作室嘉宾是 Resend 的 Zeno Rocha。我们认识要追溯到你的 VS Code 主题时代——当时我就想「不知道这人是干嘛的，但他做的一切都有品味」。现在你做了一家邮件基础设施公司。

Zeno：我到现在自我介绍还是只讲最近的经历。很长一段时间里，人们知道 Dracula（他创建的主题）多过知道 Resend——好在正在改变。（他还是 2020/2022 年 GitHub 最活跃的前二十名之一。）

为什么选邮件？说实话：如果当年知道邮件这行有多难，我大概根本不会创办这家公司。我是纯前端出身——CSS 开发者、没有基础设施背景、没有邮件行业背景。吸引我的是：这个市场规模巨大、玩家众多（Mailgun、MailChimp、SendGrid），但没有一家真正在乎开发者——他们服务营销人员、产品经理，就是不服务开发者。于是我的出发点就一句话：如果这是「邮件界的 Stripe」，它长什么样？

【数字与「日记式」冷启动】

先让嘉宾炫耀一下：430 万用户（截至今晨）、12 万付费客户；客户从 Warner Brothers、HBO 到独立开发者。彩蛋：Warner Brothers 是他早期某个周六在自己数据库里「用最笨的办法」捞出来的——按域名过滤，看到一个叫 WBD 的域名，「这是啥？哦，华纳兄弟探索公司在用我们。」logo 墙就是从那时开始收集的。

swyx（声明自己是天使投资人）：你当年给我的 memo 是我投的三十多家公司里最直白的一份——「MailChimp 卖了、Postmark 卖了、SendGrid 归了 Twilio——现在谁在做这事？」我说「成立」。另一个必须聊的：我已经配好了 Cloudflare 的邮件域名、DNS/DKIM 全套，模型还是不停跟我说「你必须加 Resend」——「我根本不需要 Resend，它却一直让我加 Resend」。所以你到底贿赂了 OpenAI 和 Anthropic 的谁？

Zeno：我真希望有得贿赂。但这正是我当初想做这件事的原因：每一代都有定义那个时刻的工具——我们记得 Heroku 的年代、Netlify、Vercel——而新一代的发行渠道跟以前不一样了。所以从第一天起我就非常专注一件事：当有人（或 agent）问起这个品类，我们必须是第一。（swyx：你现在是第一——Claude Code 推荐 Resend 的比例超过 60%。）

【邮件基础设施的内行课】

邮件落inbox与扩展普通应用完全不同：不能靠堆 GPU 或横向扩容，得「遵守游戏规则」——Gmail、Outlook、Yahoo 各有各的行为，这是个极其老派、极度依赖人脉与关系的行业。而「极度天真」是发生在我们身上最好的事：没有先入之见。比如别家开户新用户第一件事是填表单（发多少封、什么用途）、然后人工审核两天、多数还拒批——我说「这说不通，为什么拦人？」于是把摩擦全删掉、摩擦我们自己扛。当然干了三四年我现在懂他们为什么这么做了：欺诈、钓鱼、滥用泛滥，我们内部为此建了一堆疯狂系统。

给 10 万人发一封邮件：不能一口气砸给 Gmail——会被限流，因为它要先看互动信号。做法是排队：把互动最活跃的受众排到队首批次、批次间隔拉开、跨服务商错峰；买不同 IP 段、查 IP 段历史、把用户分进不同 IP 池、随时间均衡。整个一套疯狂的基建博弈。

反钓鱼的思路是「反向工程滥用者的行为、然后做完全相反的事」：滥用者买全新域名（新域名信誉差）、做仿冒域名（比如给 code outreach 单独弄个长得像主域的域名——那看起来就像钓鱼）、一次性海量发送然后沉默。所以要持续稳定地发、域名要有正常网站、信誉要养。有个日本「团伙」最近带来了两万个域名、在不同注册商用不同 TLD 注册——我们逐个因子地查。

平台应该替用户受教育：我们在产品里内置 insights、发送前的链接检查器、拼写检查器。一个早期决定：世界正在变化——agent 比以前多多了——于是我们自动为每封 HTML 邮件生成纯文本版（从 HTML 抽取 markdown 一起发）。送达率大涨：垃圾过滤器直接读内容、不用解析。

打开率已死：open tracking 靠 1×1 透明 GIF，但 Apple 隐私功能会预先读取所有邮件——这个指标整体不再可靠，只能靠点击跟踪。而点击跟踪有个大坑：链接与图片的 URL 必须与发送域一致（不然就是滥用者模式）；更糟的是共享点击域的「坏邻居」问题——同域一个客户发钓鱼、整域进黑名单、脱黑要几天到几周。我们自己也踩过。

信任哲学：别的平台像「出生在先坐十八年监狱、证明自己是好公民才放你出来」的社会。我想要「生而自由」的社会：默认信任你，但一旦从退信率、投诉率、邮箱服务商反馈里发现不对劲，立刻封锁、马上跟你聊。大多数时候是误用（misuse）不是滥用（abuse）——用swyx的话说「skill issue（技术不行）」。

【支持团队四代进化与 DNS 之痛】

支持如果是个软件，我们已经第四个大版本：V1「随便找个人坐在椅子上」；V2 领域专家但不主动；然后立了个超酷的政策——「只能带链接回复工单」：不许直接给答案，先去写文档/知识库文章再回（一张工单也许一个半小时，但链接从此反复复用，知识库就这么建起来了）。去年 12 月破百万用户、现在四百万——不能再靠堆人，全部从头重构。免费层坚决保留：「我当年就是因为 Heroku 的免费层才成为工程师的。」

今天工单的大头是 DNS——「永远是 DNS」。新一代受众（Lovable、Bolt、V0 带来的用户）不知道 CNAME、A 记录、TXT 是什么、粘错值。swyx：我现在直接让 Codex/Claude Code 用 computer use 全权管理我的 DNS 记录，它自己 dig、自己调所有 DNS——美极了。解药还有 Domain Connect 协议——「域名的 OAuth」：点按钮、什么都不用填、没有出错机会。我们去说服了 Vercel 加入、Cloudflare 也在；GoDaddy 对此收费离谱、Ionos 谈了好几个月、协议几乎无人维护——但这个方向美极了。

【React Email：他们的 Next.js】

React Email 是开源的获客渠道——相当于我们的 Next.js。我故意做了些事：文档里写了「怎么配 SendGrid、MailChimp、Mailgun」——每一篇都是我亲手写的。策略就是「给、给、给、然后再要」（Gary Vee 式）：先修好旅程第一段（写模板太痛苦：设计师给 Figma、你切成 HTML 表格、内联 CSS、Outlook 还有特殊注释——一团糟），React Email 本质是个编译器：Tailwind token 直接导入、TypeScript 校验、写一次到处能跑。有人质疑「你这根本不是 React，没有 state」——对，就是 JSX 模板：邮件里不能带 JavaScript，而 CSS 反而是图灵完备的（笑）。

【前辈们的课：Mailgun、SendGrid、Twilio、SES】

Mailgun 创始人 Ev 的忠告：「我们 90% 的研发都在对抗滥用者——这生意糟透了，别进来。」这教会我：必须自动化，安全不能成为核心业务。SendGrid 一直是那个 behemoth——「怎么可能打败」——然后今年 npm 下载量反超、现在两倍。Twilio 是我极敬佩的公司、他们基本发明了 DevRel（「ask your developer」广告牌）；现在 Jeff 走了、CFO 去买了 The Onion——他们在 SendGrid 上睡着 了、SMS 上也是。我的思考：这个行业的规模经济到底在哪？他们比我们大一百倍，为什么不能用规模直接赢？也许根本没有规模优势——你只要做出更好的产品，慢慢就能到。

AWS SES：我们自己也是从 SES 起步（在其上做 DX 层创新：全语言 SDK、Serverless/Lambda 教程——当时没人写这些）。SES 的隐藏成本：5K 看似便宜，但事件要 SNS、日志要 CloudWatch、队列要 SQS、webhook 要自建——足迹迅速膨胀。AgentMail 就明确说了建在 SES 上不跟它竞争。而我们现在的方向相反：going down to the metal——自建底层基建（干了几个月、快宣布了）。最难的是 IP：整段购买、自管 IP 池、对各邮箱服务商做流量管制、维护关系。动机是可观测性：工程师想知道「这封真的送达了吗？进垃圾箱了还是促销标签页了？」——离金属越近、能透出的数据越多。性能也在重做：我们一直是 Node/TypeScript 公司，发送路径已换成 Go。swyx：现在语言不再重要了——我自己在跑 Rust 项目、但根本不会 Rust。

【Designing for Agents：MCP 的正确姿势】

几个月前人人喊「MCP 死了、只有 CLI 才重要」。我不追潮流，我只想让产品「无形」（formless）：用户想怎么用就该怎么用——所以一直 API first（没想到这在后来帮了我们这么大）。MCP 调用量每月翻倍、8 月底已达 120 万次。冷知识：我们第一个 MCP 是投资人 a16z 的 Yoko 写的开源本地版，火了之后我问她「能不能转给我们组织」。要做对远程 MCP，被迫回炉整个权限体系：先建 OAuth、再理 RBAC、再上可观测性（Datadog 全套）、最后是发行——进各家官方商店与插件市场。官方性重要吗？swyx 现身说法：Plausible 的 MCP 是 Sentry 建的，「我爱 Sentry，但这段集成的所有权必须在软件主人手里」——所以我们把 Plausible 换成了 PostHog。

与 Cloudflare「只暴露两个 MCP 工具」的极简路线相反，我们走了 80+ 工具的大而全（还在加）：目标是仪表盘能做的 100% 都能通过 MCP 做——包括用量、计费、团队邀请、provisioning 这类敏感区（暴露与否的经典两难：90% 覆盖率留一手 vs 全暴露）。

【Next.js 的教训与 CLI 招聘】

我们犯过的最大架构错误之一：dashboard 用 Next.js 的 server components 把数据绑死在页面上——默认没有公共 API。原则应该是：永远做 headless 后端，前端只是众多客户端之一（对人类是网页、对 agent 是 MCP）。现在 dashboard 是消费自家同一套 API 的私有客户端、monorepo 统一管理；另外当年从 Next 迁回 node server 有个朴素原因——账单太贵。

CLI 招聘：现在有三种方式加入 Resend——网页、CLI、API。用 CLI 来应聘的简历会被单独过滤、获得特别关注；招聘相关的 skills 直接烘焙进 CLI。

【多人文档编辑与 Inbound 收件箱】

我们在 Resend 里内置了多人实时编辑：all-hands 全员（20 来人）在同一个文档里一起写周报邮件、一起发送。下一个抽象是 inbound：给 agent 们配几十上百个收件箱——已读/未读、星标、打标签的全套 API，产品很快发布（对标 Missive、Front、Help Scout 的 agent 原生版）。

【送达率的现代玩法】

信誉体系已从 IP 转向域名。用子域名隔离信誉：marketing.、transactional.、confidential.resend.com 各管各的——营销邮件出事不连坐交易邮件。坚持用 .com：奇怪 TLD 看起来就像钓鱼。Apple 隐私邮箱地址也带来一堆适配活。

【AEO 实战：让模型说对话】

我们的 AEO（agent engine optimization）打法：文档覆盖长尾（Django 等框架的接入 FAQ）、每个页面都有 .md 版本（URL 后缀直接加 .md、内容协商）、docs 用 Mintlify 挂 llms.txt——营销站也挂。经典事故：定价计算器是 JS widget、agent 不执行 JS，于是模型一度声称「Resend 定价不透明」——我们做了纯文本 .md 版把数据写死，模型的话术立刻被纠正。对比图、采用曲线全部转成文字版；404 页给最近邻推荐；为 Claude Code/Codex 专门做了接入页。还观察到 Opus 4.5 的推荐有 recency bias——新东西更容易冒头，所以持续有新动作、自然提及变得更重要；Reddit/HN/Twitter 的权重在下降。我们订了四家 AEO 工具（Profound 等）——但它们都是「报告工具」不是「行动工具」（swyx：像当年的 Moz，但 Moz 敢给观点）。swyx 自己的循环：CMO agent 再生 agent、开实验窗口、Ahrefs+dataforseo+自建 AEO 追踪器。

【销售、定价与个人选择】

企业销售刚起步：只有一个 AE，小心翼翼一层层保护文化。企业版是「不同的产品」——不只是定价页上加 SSO/SCIM/审计日志。营销邮件与事务邮件的定价之争：按联系人计价的模式正在被 AI 公司打破（有的公司增长速度疯狂——比如 Mistral）。发送引擎对大批量做批次、间隔、按域限速：430 万订阅者的 newsletter 要发一天多——「多付钱进不同的队列」，跟 token 限速一个道理。

最后聊个人：我是 W23 那届最年轻的父亲之一。YC 那 250 家公司，我想当第一名——后来明白这是无限游戏。有位合伙人当年对我说：「你太在乎设计了，不然你早就更进一步了。」这话伤到我，但我决定跟随自己的信念：一个一千用户、有身份认同的产品，好过一万个用户、我不爱的产品。宁可 1000 万 ARR、女儿愿意跟我玩，不要一亿 ARR、女儿疏远我。我常觉得自己是个糟糕的爸爸/丈夫/CEO——居家办公、在三个角色间切换；我们搬回了巴西，第二个孩子快出生了。
